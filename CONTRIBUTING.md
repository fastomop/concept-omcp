# Contributing to concept-omcp

Thanks for your interest in improving concept-omcp. This document covers the
practical workflow and the policy for AI-assisted contributions.

## Quick start

The project uses [uv](https://docs.astral.sh/uv/) end-to-end.

```sh
uv sync --frozen --extra dev --extra build   # dev tools + the build pipeline
uv run --frozen --no-sync pytest             # hermetic unit suite
uv run --frozen --no-sync pytest -o addopts=""  # full suite (incl. integration)
uvx ruff check src tests eval examples       # lint
uvx prek run --all-files                     # pre-commit hooks
```

See [AGENTS.md](AGENTS.md) for the full command reference, layout, and conventions.

## Developer's Certificate of Origin

We use the [Developer Certificate of Origin](https://developercertificate.org/) (DCO).
By signing off on a commit you certify that you wrote the patch or otherwise have the
right to submit it under the project's licence. Sign off with:

```sh
git commit -s -m "your message"
```

which appends a `Signed-off-by: Your Name <you@example.com>` trailer.

## AI-assisted contributions

AI tools are welcome, but accountability stays with the human author.

1. **Disclose and take responsibility.** If a patch was substantially generated by an
   AI tool, say so in the PR description (which tool, what it did). You — the submitter —
   are responsible for the code: you have read it, understood it, tested it, and stand
   behind its correctness and licensing, exactly as if you had written it by hand.
2. **No unreviewed bulk output.** Don't open PRs that you have not personally reviewed
   end to end. "The model wrote it" is not a defence for a regression.

## Standard PR checklist

- [ ] `uvx ruff check src tests eval examples` and `uvx ruff format --check …` pass.
- [ ] `uv run pytest -o addopts=""` passes (full suite, including integration).
- [ ] New/changed behaviour has a test (extend `tests/`; reuse `tests/fixtures/athena/`).
- [ ] `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md) updated for any user-visible change.
- [ ] Docs/README/AGENTS updated and stale references swept (see AGENTS.md → *After making changes*).
- [ ] Commits are signed off (DCO).
- [ ] **No vocabulary data or built artifacts committed** (they are licence-encumbered).

## Reporting issues

Open a [GitHub issue](https://github.com/fastomop/concept-omcp/issues) with a minimal
reproduction: the query/command, the relevant settings (`CONCEPT_OMCP_*`), and what you
expected versus what happened. For security reports, see [SECURITY.md](SECURITY.md) —
do not file vulnerabilities as public issues.
